# Сайт «Фруктовый Дом» — frudom.ru

Отдельный проект, к генератору документов (frudom-docs) не относится.

## Как устроено
- `server.js` — сайт (Node 20+, без внешних библиотек). Каждая страница собирается на сервере, поэтому Яндекс видит товары, цены и тексты сразу.
- `lib/data.js` — каталог из листа «Витрина» таблицы «Магазин Фруктовый Дом» (через `server/Code.gs`), обновляется каждые 5 минут; если таблица не отвечает — `catalog.json`.
- `lib/render.js` — страницы (оформление как на frudom.ru/test): главная, `/catalog`, `/catalog/<категория>`, `/catalog/<категория>/<товар>`, `/dostavka-i-oplata`, `/kontakty`, `sitemap.xml` (с картинками), `robots.txt`, фиды `/feed/yandex.yml` и `/feed/google.xml`.
- `public/` — стили, корзина (`site.js`), общие правила цены (`shared.js`, их же использует сервер).
- `/api/order` — заказ уходит в Apps Script (лист «Заказы с сайта» + письмо).
- `/1c` — генератор документов: пропускается на страницу Тильды как есть (запасной вариант — копия с GitHub).
- `server/Code.gs` — скрипт таблицы «Магазин Фруктовый Дом» (Даниил вставляет вручную).

## Настройки сервера (переменные окружения)
| Переменная | Что | По умолчанию |
|---|---|---|
| `SITE_URL` | адрес сайта для canonical и sitemap | `https://frudom.ru` |
| `METRIKA_ID` | номер счётчика Яндекс Метрики | пусто (счётчик выключен) |
| `GS_URL` | адрес веб-приложения Apps Script | вписан в `lib/data.js` |
| `TILDA_ORIGIN` | системный адрес Тильды для `/1c` | `https://project8349547.tilda.ws` |
| `TILDA_PATHS` | страницы, которые остаются на Тильде и открываются через сайт как есть | `/1c,/pdf` |
| `PORT` | порт | `3000` |
| `TRUST_PROXY` | сколько своих прокси перед сайтом (для лимита заказов по адресу); 0 — не верить `X-Forwarded-For` | `0` |

## Реклама (Яндекс Директ, Google Ads)
| Переменная | Что |
|---|---|
| `METRIKA_ID` | счётчик Яндекс Метрики (с электронной коммерцией: просмотр товара, добавление, покупка) |
| `GA_ID` | Google Analytics 4, вида `G-XXXXXXX` |
| `GADS_ID` | Google Ads, вида `AW-123456789` |
| `GADS_ORDER_LABEL` | метка конверсии «Заказ» в Google Ads (часть после «/» в send_to) |
| `YANDEX_VERIFICATION`, `GOOGLE_VERIFICATION` | коды подтверждения сайта в Яндекс Вебмастере и Google Search Console (из мета-тега) |

Цели (Метрика и Google): `add_to_cart`, `cart_open`, `checkout_start`, `order_sent` (сумма, тип), `phone_click`, `email_click`, `repeat_order`.
Фиды товаров: `/feed/yandex.yml` — Яндекс Директ (товарная кампания), `/feed/google.xml` — Google Merchant Center. Обновляются вместе с ценами.
Метки перехода (utm, yclid, gclid) запоминаются на 30 дней и сохраняются в заказе (видно в карточке заказа в /admin).
Картинки товаров: своё фото из колонки «Фото» «Витрины» (лучше всего для рекламы) или нарисованная (`public/art.js`, `/img/p/<категория>/<товар>.svg`).
Для фидов и соцсетей нужны JPG — `public/img/…`; после добавления новых товаров: `node server.js`, затем `python3 tools/render-images.py http://localhost:3000`.

## Личный кабинет покупателя `/account` (вместе с базой заказов)
- `lib/account.js` — вход по коду на почту (6 цифр, 10 минут, 5 попыток, не больше 3 кодов за 15 минут на почту), заказы покупателя (оформленные из кабинета или на ту же почту), карточка заказа (шаги «Принят → Подтверждён → Оплачен → Собран → Доставлен», товары, суммы, оплата, счета, история), «Повторить заказ», профиль и реквизиты компании (подставляются в заказ), выход.
- Письмо с кодом отправляет таблица: действие `shopMail` в `server/Code.gs`. Ключ сайт создаёт сам и присылает с письмом; таблица запоминает первый ключ (свойство скрипта `MAIL_KEY`). Если сайт переехал на новую базу — удалить `MAIL_KEY` в Apps Script → Настройки проекта → Свойства скрипта.
- Лимит Google: около 100 писем в день для обычного аккаунта Gmail (1500 — для Google Workspace).
- Для проверки без писем: `MAIL_DEV=1` — код печатается в журнал сервера.
- Проверка: `node test/account-check.js` → «ошибок: 0».

## Проверка
`node test/site-check.js` → в конце «ошибок: 0» (сам поднимает тестовую таблицу, сайт и заглушки).
`node test/orders-db.js` → «ошибок: 0»: база заказов и статусы (расчёт сайта = расчёту таблицы на 600 случайных заказах, повтор заказа, устаревший каталог, взвешивание и доплата, счёт → оплата → сборка, запрет отгрузки без полной оплаты, отмена, одновременная правка, перезапуск и копия базы, очередь копий в таблицу).
`node test/order-security.js` → «ошибок: 0»: защита заказов (подмена цены, неизвестный товар, количества, повтор заказа, формулы в таблице, лимит).

Заказ: браузер шлёт только товар, количество, способ (кг/мешок), контакты и итог для сверки; цену, доставку и НДС считает `server/Code.gs` в копейках. План запуска оплаты — `docs/LAUNCH-PLAN.md`.

Адрес `www.frudom.ru` сайт сам перенаправляет на `frudom.ru`; технический адрес хостинга (`…twc1.net`) закрыт от поисковиков (noindex).

Старые файлы `index.html` и `embed.js` — временная версия для Тильды (frudom.ru/test), удалим после переезда домена.

## База заказов (этап 2, включается переменной `ORDERS_DB`)
- `lib/pricing.js` — расчёт заказа (копейки, граммы), те же правила, что в `server/Code.gs`.
- `lib/db.js` — база заказов: **PostgreSQL** (`ORDERS_DB=postgres://…?sslmode=require` — облачная база Timeweb, данные не пропадают при обновлении сайта) или файл SQLite (`ORDERS_DB=путь.db` — для проверки). Функции асинхронные, запросы по очереди через одно соединение, транзакции (`db.tx`), миграции сами при запуске.
- `lib/pg.js` — свой клиент PostgreSQL без сторонних пакетов: TLS, вход SCRAM-SHA-256, параметры отдельно от текста запроса, переподключение после обрыва.
- Сайт запускается и без базы: пока база не подключилась или недоступна, заказы уходят сразу в Google Таблицу (с пометкой «БАЗА НЕДОСТУПНА»), повтор подключения каждые 30 с; `/admin` в это время отвечает 503.
- `lib/orders.js` — заказ (ключ повтора), три статуса: `order_status`, `payment_status`, `fulfillment_status`; разрешённые переходы; **отгрузка только при полной оплате окончательной суммы**; взвешивание и пересчёт; счёт; ручное подтверждение оплаты с основанием; отмена; история и журнал «кто, что, когда»; защита от одновременной правки (версия заказа).
- `lib/outbox.js` — очередь: копия заказа в Google Таблицу (и письмо владельцу) с повторами, ключ `db-<номер>`.
- Если каталог из запасного файла или старше 30 минут — заказ принимается со статусом «цены не подтверждены»: счёт, оплата и сборка закрыты, пока менеджер не нажмёт «пересчитать».
- `/health` показывает базу, возраст цен и очередь; проблемы базы — в поле `warn` (ответ остаётся 200, чтобы хостинг не перезапускал работающий сайт). Подробности ошибок и адрес базы — только в логах.
- Проверка: `node test/orders-db.js` (SQLite) и `PG_TEST_URL=postgres://…/postgres node test/orders-db.js` (+ PostgreSQL) → «ошибок: 0».

## Кабинет менеджера `/admin` (вместе с базой заказов)
- `lib/admin.js` — страницы: список (вкладки «Нужно действие», «В работе», «Все»…, поиск по номеру), карточка заказа (суммы, «к оплате», покупатель, товары, счета, оплаты, история) и действия: пересчитать цены, выставить счёт, отметить поступление денег (сумма, дата, способ, основание), начать сборку, фактический вес, готов к отгрузке → отгружен → доставлен, отмена с причиной. Все правила — в `lib/orders.js`.
- `lib/auth.js` — вход: `ADMIN_USERS` (имя:роль:отпечаток пароля), роли admin/manager (всё) и viewer (только смотреть); сессия 12 ч в cookie HttpOnly + SameSite=Strict (+Secure при `COOKIE_SECURE=1`); 5 неудачных попыток — пауза 15 минут; ключ формы (CSRF) и проверка Origin в каждом действии; страницы не индексируются и не встраиваются, CSP без сторонних скриптов.
- Пароль → отпечаток: `node tools/hash-password.js` или страница `/admin/setup` (открыта, только пока `ADMIN_USERS` не задан: имя, права, пароль → готовая строка для `ADMIN_USERS`; пароль не сохраняется). Проверка: `node test/admin-setup.js`.
- Проверка: `node test/admin-check.js` → «ошибок: 0».
